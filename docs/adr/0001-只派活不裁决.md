# 0001 · 只派活不裁决

- **状态**：已裁决（来源：ADR-D22 / orchestration-service-design.md §1、§5）
- **场景**：编排层最容易被塞进来的东西是"顺手算个指标""顺手筛一下结果"。一旦开始解释结果，它就和 analytics 重叠；一旦开始改结果，它就和 core 冲突 —— 最后没人说得清"这个数是哪算的"。
- **决策**：本仓只做三件事：**派活、跟踪状态、留痕坐标**。不解释结果、不改结果、不重算指标；三 hash 只登记引用，不复制内容。
- **理由**：编排是"控制面"，引擎是"数据面"。控制面一旦开始处理数据，就同时承担了两种故障域，且会与 analytics 的分析口径打架。
- **代价 / 后果**：① 想看"批量结果里哪个最好"必须调 analytics 或由 ui 组合，本身不提供评分算法（Scorer 只做排序，不做新指标）；② 三 hash 需要上游都能给出（依赖 X0 落地）。
- **替代关系**：无（本仓首条）
